## Breaking (wrong financial figure shown to a user)

**B1. Zakat: switching the nisab standard quickly could produce a nisab ~70x too high and a false "zakat not due" verdict.**
- Where: `assets/zakat-calc.js`, `loadNisab()`.
- What: each switch of the silver/gold dropdown starts a new price fetch, but nothing stopped an older, slower response from landing last. Silver -> gold -> silver with a slow gold response left the gold per-gram price (~$192/g) multiplied by the silver weight (612.36g). Reproduced on the original code: nisab shown as **$117,573.87** with silver selected, and a user with $20,000 was told "Below nisab, zakat is not due" (correct: $500 due).
- Fix: each fetch gets a sequence number; only the newest request may write state. The previous metal's price is also cleared the moment a new fetch starts, so it can never be paired with the other metal's weight. Verified with a deliberately delayed gold response: nisab stays on silver, verdict correct.

**B2. Tax: HECS-HELP repayment ignored salary sacrifice (understated by 15-17c per dollar sacrificed).**
- Where: `assets/tax-calc.js`, `computeBreakdown()`.
- What: HELP repayment income includes reportable super contributions (salary sacrifice), but the calculator used taxable income only. Example: $100k salary, $20k sacrificed, HECS: showed repayment **$1,571** and take-home **$62,309**; correct is **$4,571** and **$59,309** (a $3,000 overstatement of take-home pay).
- Fix: HECS is now calculated on taxable income + sacrifice (the 10% cap applies to that same figure). Verified.

**B3. Tax: Medicare Levy Surcharge tier ignored salary sacrifice.**
- Where: same function.
- What: "income for MLS purposes" also adds back reportable super contributions. Example: $115k salary, $15k sacrificed, no private cover: showed MLS **$0**; correct is **$1,000** (tier 1, 1% of $100k taxable).
- Fix: the tier is now tested on taxable income + sacrifice and the surcharge is charged on taxable income, which is how the ATO applies it. Verified.

**B4. Tax: Medicare levy over-charged for families with children in the shade-in band.**
- Where: `medicareLevy()` / old `medicareLevyThresholds()`.
- What: the family lower threshold rises $4,338 per child, but the switch-over to the flat 2% was hardcoded at lower + $11,809 instead of 1.25 x lower. With children, incomes between the two points were charged the full 2%. Example: 3 children, $74,000: showed **$1,480**, correct **$1,374.80**. Small dollar amounts, narrow band, but a wrong figure.
- Fix: levy is now simply min(2% of income, 10c per dollar over the lower threshold), which is the exact rule for every household type. Singles and childless families unchanged (verified). The now-unused upper-threshold helper was removed.

## Significant

**S1. Zakat: typing a ticker lost focus after the first character.**
- Where: `assets/zakat-calc.js`, `renderShareRows()` input handler.
- What: every keystroke in the ticker box re-rendered the row, destroying the input. Typing "BHP" left just "B" in the box, so the ASX ratio lookup (a headline feature) effectively didn't work for keyboard users.
- Fix: after the re-render, focus and cursor position are restored to the new ticker input. Verified "BHP" types fully and the precise-method figure (10,000 x (cash 8.3% + receivables 2.2%) = $1,050) is correct.

**S2. All four calculators: results went stale when inputs changed.**
- Where: all four JS files (button-only handlers).
- What: after pressing Calculate, editing any field left the old result on screen until the button was pressed again, so the displayed figures could silently contradict the form (e.g. change salary to $120k, still showing $63,880).
- Fix: once a result is showing, it recalculates automatically when any input changes (tax, zakat and hourly on every edit; growth on commit/blur, because its field-clamping would otherwise fight the keyboard). Auto-updates don't scroll the page. Zakat also now re-runs when a manual metal price is typed or a holding is removed. Verified on every calculator.

**S3. Tax: salary sacrifice larger than salary inflated "Total super".**
- Where: `computeBreakdown()`.
- What: $10k salary with $50k "sacrifice" showed total super **$51,200**.
- Fix: sacrifice is clamped to the salary. Now $11,200. Verified.

## Minor

**M1. Hourly: headline rate rounded to whole dollars.** `$80k -> "$32/hour"` (true $32.33); for net $60k/40h it showed $29 vs $28.85. A 1-2% error on the headline number. Fixed: hourly rate now shows cents (`$32.33/hour`). The items table already used the unrounded rate, so hours-of-work figures were unaffected.

**M2. Hourly: hours field not validated.** 0 or blank silently used 38 while the box still showed 0; 500 hours/week was accepted (result $2/hour). Fixed: clamped to the input's own 1-100 range, blank/0 falls back to 38, and the value actually used is written back to the field.

**M3. Growth: fractional years ran a different number than shown.** Typing 2.5 projected 3 years while the box still said 2.5. Fixed: the rounded value is written back.

**M4. Tax page copy contradicted the calculator.** Intro said the calculator assumes "no dependents", but the Advanced section models dependants and spouse. Reworded in `tax-calculator/index.html` (page copy, not course JSON).

## Needs a decision (not fixed, not a bug in the arithmetic)

1. **Hourly calculator counts 52 working weeks a year.** Salary includes ~4 weeks paid leave + ~2 weeks of public holidays not actually worked, so "hours worked" is overstated by roughly 11% and the "real hourly rate" is understated by the same (e.g. $32.33 on 52 weeks vs ~$36.50 on 46 weeks). The page copy says "divide by the hours you worked", which argues for 46-48 weeks, but any course content quoting hourly figures would need to move with it. Your call.
2. **Medicare levy low-income thresholds** ($28,011 single, $47,238 family, +$4,338 per child) are not independently confirmed; the page already discloses them as "current best figures". Only matters for incomes under ~$35k (single). Worth a check against the ATO once the FY2026-27 figures are published.
3. **Paywalled copy is stale.** `shariah-invest-au-build/paywall/dist-site/` is a copy of the live folder made by `build-gated.mjs` and still holds the pre-fix calculator JS. If that folder is what gets deployed, re-run `node build-gated.mjs` first. I did not run it (it's your gated-deploy workflow).

## Launch-ready?

**Yes, as of these fixes.** Before them, no: the zakat nisab race could tell a user with zakat due that none was owed, and anyone combining HECS or no-private-cover with salary sacrifice got an overstated take-home figure, both genuinely wrong financial answers. With the fixes in, every calculator reproduces independently hand-computed figures (including the $80,000 -> $63,880 checkpoint), handles $0 / empty / negative / $50M input cleanly, updates live, and throws no errors across 56 new checks plus all six existing suites. The only open items are the working-weeks assumption in the hourly calculator (a methodology choice, not a math error) and making sure the gated `dist-site` copy is rebuilt before deploy.
